Build the `information_schema` partition predicate explicitly, now that the bare `Column` no longer carries operators. `MariaDBPartitionMixin.format_get_partitions_expression` compared columns with `Column(...) == FunctionCall(...)` and `== Literal(...)`, which after the core's column-layer rebuild falls through to a Python `bool` instead of building a predicate -- a silent failure, since nothing raised and the query that came out could not work. The two comparisons are now `ComparisonPredicate` nodes, so the rendered SQL is unchanged and correct. The same migration runs through `examples/named_expressions/order_expressions.py`, where every `where=Column(...) == Literal(...)` becomes an explicit `ComparisonPredicate`.
