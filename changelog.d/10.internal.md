Python 3.15 becomes a required CI leg rather than an experimental one: `continue-on-error` and the `3.15.0-rc.2` pin both go, and the leg now covers the GIL and free-threaded builds alike. The `Programming Language :: Python :: 3.15` classifier is declared, and the testsuite install line in `test.yml` moves to `@test/typed-column-contracts` to match the coordinated testsuite branch.

`pydantic` 2.12.2 / `pydantic-core` 2.41.4 are pinned for Python 3.13, including the free-threaded `3.13t` build. The `python_version` marker distinguishes release lines, not GIL configuration, so both 3.13 builds are covered by these two lines. The pin has to be restated in `requirements-dev.txt` because that file is installed *before* the core package: resolving an unpinned `pydantic` there picks a `pydantic-core` whose only `cp313t` distribution is an sdist, and the build then fails on the free-threaded jobs before the core's own pin is ever in scope.
