Add `ALTER TABLE ... EXCHANGE PARTITION` support to the MariaDB backend. `MariaDBExchangePartitionExpression` (`expression/partition.py`, re-exported from the backend's `expression` package) names the partitioned table, the partition and the exchanging table, and `format_exchange_partition_statement` renders the statement; the validation clause carries one parameter per spelling (`with_validation` / `without_validation`), setting both raises `ValueError` at construction, a non-`Table` argument in either table slot raises `TypeError`, and leaving both unset renders no clause. The validation options are gated by the measured `MARIADB_VERSION_BOUNDARIES['EXCHANGE_PARTITION_VALIDATION']` boundary of 11.4.0: `WITH VALIDATION` and `WITHOUT VALIDATION` are refused by name below it and rendered from it, while the bare form stays available from 10.2, and `WITHOUT VALIDATION` is honored on the server rather than parsed-and-ignored. The `supports_exchange_partition`, `supports_exchange_partition_with_validation` and `supports_exchange_partition_without_validation` probes are declared on the `MariaDBPartitionSupport` protocol.

The MariaDB dialect now answers the column-type suggestion protocol: `MariaDBColumnSuggestionMixin` carries the complete 18-entry table (`suggested_column_types()`) and the capability narrowing (`supports_column_operation()`), so which column class a common Python type means on MariaDB is this backend's own answer rather than a core default. `dict`, `list`, `tuple`, `set` and `frozenset` are all `JSONColumn` — MariaDB implements no array type, and below 10.2 there is no JSON function family at all, where `dict` answers `UNSUPPORTED` so that resolution fails at model definition and points at `UseColumnType` instead of rendering SQL the server rejects. Narrowed operations: `ilike` on `StringColumn` (MariaDB has no ILIKE operator on any version), `unnest` and `json_table` on `JSONColumn` (both are `JSON_TABLE`, measured absent on 10.5.29 and present from 10.6), and `json_equal` on `JSONColumn` (`JSON_EQUALS`, which arrived with the native arrows in 13.1). Plain equality below 13.1 is deliberately **not** narrowed: MariaDB's `JSON` is a `LONGTEXT` alias the server does not normalize, so text equality is correct here where it silently matches nothing on MySQL's native-JSON columns. `uuid.UUID` is `UUIDColumn` on every version, including those below 10.7 where MariaDB has no native `UUID` type — the native type is a storage fact and does not change what a UUID value can do.
