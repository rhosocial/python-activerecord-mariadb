Follow the core's typed-column rebuild, which removes three names this backend's public surface exposed.

`DDLSource.column_type()` is now the *declaration* accessor: it presents whatever `UseColumnType` marker the field declares, as-is, and answers `None` when the field declares no column class. SQL-type reads move to `column_data_type()` / `columns_data_type()`, and `columns_type()` is gone.

The bare `Column` no longer carries operators. It renders an identifier and keeps the shared surface -- aliasing, null tests, casting -- and an operation is reached through a typed column (`StringColumn`, `NumericColumn`, `TimestampColumn`, ...) or built explicitly as a node (`ComparisonPredicate`, `InPredicate`, `BinaryArithmeticExpression`). The old universal operator surface let every operation be called on every column, and `Column(...) == value` fell through to `object.__eq__` and returned a Python `bool`, so `find_one`, the optimistic-lock check and `restore()` all built a broken predicate without raising anything.

`DateTimeColumn` is renamed `TimestampColumn`, and the `DateTimeSupport` protocol is renamed `TimestampSupport` -- it declares timestamp precision, not date/time operations. Rename the imports; there is no behaviour change in either.
