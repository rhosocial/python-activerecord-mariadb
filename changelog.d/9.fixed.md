Fix the sequence and identity DDL. The three sequence formatters now take the concrete `CreateSequenceExpression`/`AlterSequenceExpression`/`DropSequenceExpression` core dispatches and read the fields off the object, so sequence statements render at all -- previously the old `(name, **options)` signature made core's dispatch raise `TypeError` before any SQL was produced -- and they emit the spellings the server accepts (`START =`, `INCREMENT =`, `MINVALUE =`, `MAXVALUE =`, `CACHE =`) instead of the rejected `START WITH =`/`INCREMENT BY =` forms. `ALTER SEQUENCE ... START` is gated on the new `supports_alter_sequence_start()` probe (declared `True`) rather than the CREATE-side `supports_sequence_start()`, so flipping the ALTER probe now changes the outcome; the rendered SQL is unchanged on MariaDB. `GENERATED {ALWAYS|BY DEFAULT} AS IDENTITY` is no longer rewritten to `AUTO_INCREMENT`: `supports_identity_column()` and its option probes answer `False` from measurement (every measured version rejects the standard clause with errno 1064), so the clause is refused by name, while `supports_auto_increment_column()` answers `True` and the legacy `is_auto_increment` constraint renders through `AutoIncrementClause` / `format_auto_increment_clause` so that probe is consulted.
