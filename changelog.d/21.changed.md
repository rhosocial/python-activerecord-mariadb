`item_exists()` on the MariaDB introspectors now follows core's three-case rule. Kinds the engine does not have at all (type, domain, extension, tablespace, partition function, partition scheme and full-text catalogue) answer `False` instead of raising; only a kind the engine holds without a name-only catalogue query (an index) is refused. The branch each kind takes is declared on the introspector mixin as `ITEM_KINDS_QUERIED`, `ITEM_KINDS_REFUSED` and `ITEM_KINDS_ABSENT`, and both twins answer alike.

The neutral object-state annotations now match core's non-optional `TableState.partitioning`: both `get_partition_state` twins are annotated `-> PartitionState`, and `parse_table_state` takes a `PartitionState` instead of `Optional[PartitionState]`. A table that is not partitioned is spelled `scheme=None` on the returned state -- the return value is never `None` -- so the dead `partitioning is not None` guard was removed. Behaviour is unchanged; a guard test now rejects any `partitioning=None` / `partitioning is None` / `Optional[PartitionState]` spelling in `src` and `tests`.
